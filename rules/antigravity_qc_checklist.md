# 🔍 Antigravity QCチェックリスト (Pre-Commit QC Audit)

Antigravityがコミット前のQC監査（git_safety.md 2章）を行う際の監査観点を、役割別に3つに分けて定める。

## 観点A: 仕様QC

* 成功条件リスト（git_safety.md 2.9）を全て満たしているか。未達成・未確認の項目が残っていないか。
* 既存の取込・連携フローに副作用がないか（修正対象外の経路が変更前と同一結果になるか）。
* 共有設定ファイル（.agent/project.md で定義）への変更がないか（coding_standards.md 2. 追加的変更の原則）。
* 日本語ファイル名・ディレクトリ名を対象にした収集・変換処理で、Unicode正規化（NFC/NFD）の差異による取りこぼしがないか。ファイル列挙は find のパターン一致ではなく `git -c core.quotepath=false ls-files` を基準にする（macOSではNFD形式のディレクトリ名がNFCパターンの find に一致せず、対象ファイルの取りこぼしが実際に発生した）。

## 観点B: セキュリティQC

* APIトークンのログ出力・ハードコードがないか。
* 顧客の個人情報（電話番号・住所）が Logger に生出力されていないか。
* Kintone REST API 呼び出しの権限スコープは最小か（タスクに不要なアプリへのトークン使用がないか）。

## 観点C: 単純化QC

* 単純化レビュー観点:
  * 過剰な抽象化はないか（100行で済むものを300行にしていないか）。
  * 防御的設計として必要なガードコードと、単なる冗長コードを区別できているか。
  * 同種の既存ファイルのパターンから外れていないか。
  * Dead code、使われない変数、実装と合わないコメントはないか。
  * 新しい概念・命名を増やしすぎていないか。
* 1タスク1コミットになっているか（git_safety.md 2.7 ステージング操作の制限と連動）。

## 出力形式

* 観点A・B・Cのそれぞれについて、以下のいずれかの判定を出力する: **高リスク / 中リスク / 低リスク / 問題なし**
* 「問題なし」以外の判定には、根拠となるファイル・行番号を必ず添える（git_safety.md 2.5 エビデンス添付義務に準ずる）。
