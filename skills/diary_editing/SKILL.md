# 日記の編集スキル (Voice Lifelogger)

ユーザーが音声入力した生のテキスト（日記の素材）を、AIエージェントが自動で校正・整形し、note公開用のフォーマットおよびSNS向けへ変換するスキルです。

---


> [!TIP]
> **ファイルの読み込み方**: 本スキルの追加モジュールは、本 SKILL.md が配置されているディレクトリ（<skill_root>）からの相対パスで記載されています。view_file 等のツールで読み込む際は、本 SKILL.md の親ディレクトリパス（`<skill_root>`）を起点として絶対パスを指定してください。

## 個人設定の読み込み

実行前にリポジトリルートの `config/user_profile.yaml` を YAML として読み込む。別の場所に置く場合は `DEV_STANDARDS_PROFILE` に絶対パスを設定する。未作成なら `config/user_profile.yaml.example` をコピーして編集し、設定できるまで個人向け出力を始めない。設定ファイルと参照画像は Git に含めない。
本文中の `{key}` と `{parent.child}` は、読み込んだ YAML の値への参照を示す**エージェント向け記法**であり、Markdown の自動展開機能ではない。出力前にエージェントが辞書をキーごとにたどり、文字列値へ置換する。例: `{podcast_urls.youtube}` は `profile["podcast_urls"]["youtube"]`、`{editing_log_dir}` は `profile["editing_log_dir"]`。キー欠落・空文字なら推測で補わず設定を確認する。置換前の `{...}` を記事や投稿に残さない。
`vault_path` を Vault の場所として使い、検索スクリプトを呼ぶときは `OBSIDIAN_ROOT` に設定する。`editing_log_dir` は Vault からの相対パス。

## 🧭 動的モジュール・ロード表（トークン最適化ルール）

| 実行工程 | 必須読み込みファイル | 任意参照（必要時のみ） |
| :--- | :--- | :--- |
| **ステップ0: 事前準備・バックアップ & 事例録確認** | `core/note_article.md`, 直近の `{editing_log_dir}/*.md` | — |
| **ステップ1: 2パス分離による記事整形** | `core/note_article.md`, `references/learned_rules.md` | アイキャッチ画像生成時: `workflows/avatar_image.md`（構図3原則・カタログ準拠） |

## 🚦 処理フロー概要

0. **ステップ0（事前Gitバックアップ & 直近事例録の確認）**: **編集前に必ず実行**。
   - 詳細手順は `core/note_article.md` を参照。
1. **ステップ1（工程分離・2パス生成）**: `core/note_article.md` に従い、以下の2パスで生成する。
   - **パス1（機械的コピー＋改行挿入）**: 原文の一字一句を変更・要約・省略せず、1〜2文ごとの改行・空行の挿入のみを行う（物理的に要約を排除）。
   - **パス2（見出し挿入＋最小限の誤字修正＋提案）**: パス1のテキストに見出し・区切り線・タイトル・あらすじを付与し、明らかな誤字脱字のみ修正。表現改善は本文をいじらず「提案」として別欄に出力。
   - **アイキャッチ画像生成（必要時）**: `workflows/avatar_image.md` に従い、日記の内容（日常・乗り物移動・ツーリング等）に最適な構図テンプレートと「文字なし構図3原則」を適用し、参照画像モード（言葉での顔描写禁止）を厳守して生成・エクスポートする。
2. **ステップ2（定量的・機械的チェック機構）**: `core/verification.md` に従い、主観ではなく**機械的・定量的**に監査する。
   - **文字数比率チェック**: （出力本文の文字数 ÷ 原文の文字数）が95%以上であるかを機械的に計算。下回る場合は即座に要約の発生とみなして再生成。
   - **エピソード/段落の対照突合リスト**: 原文の各ブロックが出力に漏れなく存在するかを表形式で突合。
3. **ステップ3（ユーザー確認・訂正 & 事例録の記録）**: **処理を一時停止**し、ユーザーの確認を待つ。修正があれば即時更新し、得られた知見を `references/learned_rules.md` に追記。今回のやり取り自体を `{editing_log_dir}/YYYY-MM-DD_編集事例録.md` に蓄積する。
4. **ステップ4（SNS告知文の生成）**: ユーザー承認後、`workflows/social_promotion.md` に従ってSNS告知文を生成。

## 📌 新規ノート作成時のフロントマター規約（ObsidianVault/AGENTS.md準拠）

本スキルがVault内に**新規ファイル**（`{editing_log_dir}/*.md`、note公開用整形後ファイル等）を作成する場合は、
ObsidianVaultルートの`AGENTS.md`に従い、以下の最小フロントマターを付与する。
**既存の日記原文ファイルへの遡及付与は行わない。**

```yaml
---
tags: [<該当カテゴリ。例: 自分の過去, 旅行関連>]
status: draft
source: "[[元の日記原文ファイルへのWikilink]]"
---
```
