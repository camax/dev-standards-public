# ステップ2: ボリューム・抜け漏れ・言い回し・解釈の整合性チェック機構

生成したnote用記事を原文と比較する。
必ず決定論的監査スクリプト `dev-standards/skills/diary_editing/scripts/verify_diary_article.py --original <原文> --edited <出力>` を実行し、客観的な実測値を取得して報告すること。

1. **【最重要・定量的判定】スクリプト実測による文字数比率チェック（自己申告の完全禁止）:**
   - **実測ツールの実行義務:** AIの推論や目算による文字数カウント（「だいたい○○字」等の自己申告）は**完全禁止**。必ず `scripts/verify_diary_article.py`（または `python3 -c "import re; ..."`）を実行し、**客観的な実測値を取得して報告すること**。
   - **計算対象:** 原文の文字数（空白・改行除く）と、出力本文（Markdown見出しタグ・あらすじ・区切り線・フッターを除く本文テキスト）の文字数。
   - 計算式: `保持率 = (実測出力文字数 ÷ 実測原文文字数) × 100 (%)`
   - **判定基準と再試行上限:**
     - **95%以上**: 合格（ディテールが正常に保持されている）。
     - **95%未満**: **【不合格・要約検出】**。AIが無意識に要約・省略を行ったと機械的に判定。
     - **再試行上限（最大2回まで）**:
       - 1回目不合格の場合：直ちにどの文が削られたかを洗い出し、パス1から100%復元・再生成を行う。
       - **最大2回失敗した場合**: 無限ループによる変な出力の量産を防ぐため、**自動リトライを停止**し、「文字数保持率が○%で基準に届かないため、以下の差分箇所についてユーザーの確認を仰ぎます」として、削られた疑いのある原文センテンスを一覧提示して指示を待つ。
   - 報告フォーマット:
     ```
     - 実測 原文文字数: ○○字
     - 実測 出力本文文字数: ○○字
     - 実測 保持率: ○○%（判定: 合格 / 要再確認 [試行回数: ○/2]）
     ```
2. **【機械的突合】エピソード・話題の対照チェックリスト:**
   - 原文に含まれるすべての話題・エピソード（時間、行動、情景、登場人物、思考）が、出力側に漏れなく存在するかを表形式で1対1突合して報告する。
   - 例:
     | 原文のエピソード・トピック | 出力側での該当箇所 | 判定 |
     | :--- | :--- | :--- |
     | 7:40起床、絶妙な気温、窓開けっぱなし | 第1ブロック「絶妙な気温での起床…」 | ✅ 100%保持 |
     | ゴミ出し（2週間に1度）、赤飯とコーヒー | 第1ブロック | ✅ 100%保持 |
     | ... | ... | ✅ 100%保持 |
3. **抜け漏れ・指示メモの反映チェック:**
   - 原文末尾の指示メモや指定キーワードが漏れなく反映されているか。
4. **言い回し・トーンの忠実性チェック（勝手な美文化・リライトの排除）:**
   - ユーザー特有の語り口や生々しい口語表現、本音の切れ味が、AI特有の無難な表現や一般的な美文にすり替えられていないか。
5. **解釈の忠実性チェック（勝手な推測・意図歪曲の排除）:**
   - 音声認識の不鮮明な箇所や独特の文脈を、AIが勝手に推測・深読みして論旨や事実関係を都合よく改変していないか。
6. **音声認識エラー修正の妥当性監査:**
   - 修正した主な音声認識エラー・誤字脱字の「変換前 → 変換後」の根拠を提示し、ユーザーが意図と異なる解釈になっていないかを確認できるようにする。
7. **日付整合性チェック（`verify_diary_article.py` による自動判定）:**
   - ファイル名が `YYYYMMDD.md` の場合、その日付を基準日とする。
   - H1タイトルに明示的な日付が含まれている場合、ファイル名の日付と一致しているか確認する。
   - H1の日付がファイル名と異なる場合は「日付不一致」として警告する（勝手に自動修正せず確認対象とする）。
   - H1に日付自体が含まれていない場合は「日付表記なし」と判定する（不一致とは別扱いとし、日付がないという理由だけでAIがタイトルに日付を自動追加・変更しない）。
