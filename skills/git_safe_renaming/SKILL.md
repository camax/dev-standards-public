# Git Safe Renaming Protocol (日付サフィックスの削除)

このスキルは、Gitの履歴（History）を維持しつつ、日付サフィックスが付いたファイル名（例: `script_250101.js`）をクリーンなファイル名（例: `script.js`）に安全に変更する手順を規定します。

## 1. 事前準備
- ワーキングツリーがクリーンであることを確認します（`git status` で未コミットの変更がないこと）。
- 変更後のファイル名が既に存在するか確認します。存在する場合は、上書きするかバックアップを取るかを判断してください。

## 2. `git mv` による改名
**重要**: 通常のファイルシステムコマンド（`mv`）や「削除して新規作成」は**絶対に行わないでください**。Gitの履歴が途切れます。

必ず以下のコマンドを使用してください：
```bash
git mv old_style_name_250101.js new_style_name.js
```

## 3. 検証
- `git status` を実行し、以下のように表示されていることを確認してください：
  ```
  renamed:    old_style_name_250101.js -> new_style_name.js
  ```
- 「deleted」と「new file」が別々に表示されている場合は**中止**してください。
  - `git reset HEAD` でステージングのみを解除します（作業中の変更を失う `git checkout .` は使用しないこと）。
  - `git status` で旧ファイル名・新ファイル名それぞれの状態を確認し、ユーザーに報告して指示を仰いでください（自己判断でファイルを削除・上書きしないこと）。

## 4. Conventional Commits 形式でのコミット
- 改名を履歴に確定させるため、即座にコミットします。
- コミット直前に `git diff --cached --stat` を実行し、ステージされた対象がリネーム対象ファイルのみであることを確認します。
- メッセージ形式: `refactor(scope): rename to remove suffix for clean git history`

```bash
git commit -m "refactor(shipping): rename script_250101.js to script.js to remove suffix"
```

## 5. 改名後のタスク
- **外部連携先の更新**: ファイル名が変わったことで、デプロイ先（CMS・ノーコードツールのカスタマイズ設定、CI/CD設定など）に古いファイル名を参照している箇所がある場合は、新しいファイルを再アップロード・再設定する必要があります。
- **参照の更新**: コードベース全体を検索し、古いファイル名を参照しているインポートやドキュメントをすべて更新してください。
