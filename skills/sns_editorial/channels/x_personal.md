# X本アカウント作成基準（日常の一瞬の面白さ・違和感・人間味）

- **役割**: 日常の中にある「一瞬の面白さ・気まずさ・しょうもなさ・違和感・意外性・本人らしい行動・自分へのツッコミ」を短く切り取る場所。
- **根本方針**:
  - **目的は「AIが良い投稿を書くこと」ではなく、「本人がすでに持っている良い素材を見つけて、必要最低限だけ編集すること」。**
  - **「本人の原文がすでに強い場合は、AIが邪魔をしない」を最優先する。**
  - 本人の原文が「状況が分かる」「出来事自体に面白さがある」「長すぎない」「SNS投稿として自然」であれば、AIが文章を改善しようとして言い換えすぎず、**原文をほぼそのまま採用することを優先する**。
- **採用基準**: 単なる活動報告（「靴を買った」「ご飯を食べた」「どこかへ行った」等）はスキップ。本人だから出てくる具体的な体験の面白さがある場合のみ採用。
- **トーン**: 短い（80〜120字程度）、ラフ、口語的、説明しすぎない、無理な教訓化なし、無理な自虐なし。
- **【最重要】初見でも一読で状況が分かる最低限の前提を入れる**:
  - 「初見の読者が1〜2秒で理解できるか」は時間数値ではなく概念として扱う。本質は **「初見の読者が一読で状況を理解できる、最低限の前提が入っているか」**。
  - 「なぜそこへ行ったのか」「なぜその出来事が起きたのか」「誰との話なのか」など、面白さを理解するために不可欠な情報だけを冒頭または最初の1文で補う（背景説明を増やしすぎない）。
  - 判断基準：**「初見でも一読で状況が分かるか」**。
  - ❌ 悪い例: 「試作品を見に行った。」（なぜタダなのか、誰からもらうのかが不明）
  - ⭕️ 改善例: 「知人が試作品を見せてくれるというので、駅前の店に行った。」（必要な前提が1文で分かる）
- **【最重要】Strength Checkの本質（強い言葉自体の禁止ではない）**:
  - **「強い言葉自体を禁止する」のではなく、「一次情報より強度を上げることを禁止」する。**
  - 本人が一次情報で実際に「全然」「かなり」「完全に」「最高」「最悪」などの言葉を使っている場合は、そのまま使用してよい。
  - 禁止するのは、**原文にない強い言葉をAIが勝手に追加して強度を上げること**（例: 原文「話が盛り上がらなかった」 → 生成「全然会話が弾まなかった」はNG）。
  - 同様に、原文より意味・感情・相手への印象を強める言い換え（「少し」→「かなり」、「話が盛り上がらなかった」→「全然会話にならなかった」、「付き合うことになった」→「付き合わされた」等）を禁止する。
- **【最重要】「面白い出来事にAIがオチを足さない」（読者の余白を残す）**:
  - 出来事そのものにすでに面白さ・ズレ・しょうもなさがある場合、AIが最後に自虐ツッコミやオチを追加しない。
  - 余計な説明を削り、出来事の面白い部分だけを残して、読者が自然に「何しに行ったんだw」「それはつらい」と心の中でツッコミを入れられる余白を残す。この余白もSNS投稿の価値として扱う。
  - オチを使用してよい例外条件:
    1. 本人が一次情報で実際に自分へのツッコミを書いている
    2. ユーザーとの壁打ちでその表現を明示的に承認している
    3. オチを削ると出来事の意味が分かりにくくなる
    ※それ以外はAIが新しいオチを作らない。
- **X本垢の制作優先順位**:
  1. 面白い素材を見つける
  2. 原文だけでSNS投稿として成立するか確認する
  3. 成立するなら本人の文章を可能な限り残す
  4. 必要な前提だけ補う
  5. 不要な部分だけ削る
  6. 原文より意味・感情・評価を強めない
  7. テンポを必要最低限だけ整える
  8. AIによるオチや説明を足さず余白を残す
- **最終チェックリスト**:
  - [ ] 初見でも一読で状況が分かるか？
  - [ ] 必要な前提を削りすぎていないか？
  - [ ] 本人の原文がすでに成立しているのに、AIが不要に言い換えていないか？
  - [ ] 原文より感情・評価・ニュアンスを強くしていないか？
  - [ ] オチを足さなくても出来事そのもので成立しているか？
- **スキップ**: 強いネタがなければ「今回はX本垢スキップ推奨」とする。
